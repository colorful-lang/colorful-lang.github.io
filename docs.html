快速开始

这篇文档假设你的电脑上什么都没有。跟着做，十分钟内你会跑起第一个 Colorful 程序， 并且拥有实时诊断、补全与格式化的完整开发体验。

最短路径：只装 VSCode 插件就够了 —— 插件内已经打包了编译器、语言服务器、 格式化器、测试器、包管理器、runtime 与标准库。

从零开始

1准备环境

只有「从源码构建」才需要编译器与构建工具。如果你只打算用编辑器写代码， 可以直接跳到第 2 步的路线一。

需要什么 用途 下载
Visual Studio Code 编辑器，提供高亮、诊断、补全、跳转与格式化 code.visualstudio.com
Visual Studio 生成工具 Windows 上从源码构建工具链（勾选「使用 C++ 的桌面开发」） visualstudio.microsoft.com
CMake 3.20+ macOS / Linux 构建（Windows 也可用） cmake.org
Git 克隆仓库 git-scm.com
LLVM 15+ （可选） 想要进程内 LLVM 代码生成时才需要；默认走内置 C 后端 releases.llvm.org

2安装工具链

路线一 · 只装编辑器插件（推荐，无需构建）

  1. 从 插件发布页 下载 colorful-lang-0.1.0.vsix；
  2. 用下面的命令安装，或把 .vsix 拖进 VSCode 的扩展面板；
  3. 执行一次 Developer: Reload Window。
终端
code --install-extension colorful-lang-0.1.0.vsix --force

插件内置的工具位于扩展目录的 server/<平台>-<架构>/， 查找顺序是：colorful.*.path 设置 → 工作区的 build/ bin/ lib/ 等目录 → 插件内置 → PATH。 所以你也可以之后换成自己构建的版本，不会冲突。

路线二 · Windows 从源码构建

命令提示符
git clone https://github.com/colorful-lang/colorful.git
cd colorful
scripts\build-windows.bat

脚本会编译编译器与全部工具，产物落在 build\：colorc.exe、 colorlsp.exe、colorfmt.exe、colortest.exe、 colorpkg.exe、colorlib.exe。

路线三 · CMake（macOS / Linux / Windows）

终端
git clone https://github.com/colorful-lang/colorful.git
cd colorful
cmake -S . -B build
cmake --build build --config Release

产物在 build/bin/。若要让插件使用它们，把路径写进设置即可：

.vscode/settings.json
{
  "colorful.compiler.path": "/abs/path/colorc",
  "colorful.languageServer.path": "/abs/path/colorlsp",
  "colorful.formatter.path": "/abs/path/colorfmt",
  "colorful.testRunner.path": "/abs/path/colortest",
  "colorful.packageManager.path": "/abs/path/colorpkg"
}

3确认编辑器已就绪

新建一个 .cf 文件，状态栏应该出现 Colorful：

  • 打字时未定义名称、类型不匹配等错误会即时标红（编辑器下方 Problems 面板可看全部）；
  • Ctrl+Space 触发补全，F12 跳转定义，Shift+F12 查找引用；
  • Shift+Alt+F 用 colorfmt 格式化；
  • Ctrl+Alt+R / B / T 分别运行、构建、测试当前文件。
若状态栏没有出现 Colorful，点击状态栏或用命令面板执行 Colorful: Show Output Channel 查看原因；把 colorful.logging.level 设为 debug 会打印工具查找过的每一个目录。

第一个程序

新建 hello.cf：

hello.cf
### 我的第一个 Colorful 程序

def main():
    print("Hello, Colorful!")
    print("2 ** 10 =", math.ipow(2, 10))
    print(f"16 的平方根是 {math.sqrt(16.0)}")


# 程序入口：顶层调用 main()
main()

三点值得注意：math 这类标准库模块**不需要 import**，用短前缀直接调用； f"..." 是插值字符串，花括号里可以写任意表达式；程序从顶层第一条语句开始执行， 惯例是把逻辑放进 main() 再调用它。

编译与运行

终端
# 编译成可执行文件
colorc hello.cf -o build/hello

# 直接运行
build/hello

# 或者一条命令编译并运行
colorc hello.cf --run

# 加优化、开启更多检查
colorc hello.cf -o build/hello --opt 3

产物是普通的原生可执行文件，可以直接分发，不需要安装任何 Colorful 运行时。

想看看中间产物？ --emit c 输出生成的 C 代码， --emit llvm 输出 LLVM IR，--emit hir / --emit mir 输出编译器内部表示，用来理解某段代码是怎么被编译的。

语言速览

下面是写真实程序需要知道的全部内容，每一段都可以直接落进同一个文件里跑通。

变量与类型

types.cf
def main():
    name = "Colorful"          # str
    count = 3                 # int
    ratio = 0.75              # float
    ready = True              # bool
    nothing = nil             # 空值
    items = [1, 2, 3]        # list[int]
    scores = { "a": 90 }      # dict[str, int]

    # 需要时可以显式标注类型
    total: int = 0
    names: list[str] = ["x", "y"]

    print(name, count, ratio, ready, nothing)
    print(items, scores, total, names)
除法要注意： / 总是产生 float， 整数商要用 //，取余用 %。例如 7 / 2 是 3.5，7 // 2 才是 3。

函数

functions.cf
def area(w: float, h: float) -> float:
    return w * h


# 不写参数类型就是泛型：编译器为每个调用点单独实例化
def first_or(xs, fallback):
    if len(xs) == 0:
        return fallback
    return xs[0]


def apply_all(xs, fn):
    out = []
    for x in xs:
        out.append(fn(x))
    return out


def main():
    print(area(3.0, 4.0))
    print(first_or([7, 8], 0))
    print(apply_all([1, 2, 3], def(n): return n * n))


main()

控制流

control.cf
def classify(n: int) -> str:
    if n < 0:
        return "negative"
    elif n == 0:
        return "zero"
    else:
        return "positive"


def main():
    for i in range(1, 4):
        print(i, classify(i))

    n = 3
    while n > 0:
        print("countdown", n)
        n -= 1

    for word in ["a", "bb"]:
        if len(word) == 1:
            continue
        print("longer:", word)

    if n == 0 and not False:
        print("done")


main()

record 与 protocol

record 是值类型，按字段顺序构造；可以在 record 上定义方法。 protocol 是接口，靠方法集合隐式匹配，不需要显式声明实现。

shapes.cf
record Point:
    x: float
    y: float


def Point.length(self) -> float:
    return math.sqrt(self.x * self.x + self.y * self.y)


protocol Shape:
    def area(self) -> float


record Circle:
    r: float


def Circle.area(self) -> float:
    return 3.141592653589793 * self.r * self.r


def describe(s: Shape) -> str:
    return "area = " + str(s.area())


def main():
    p = Point(3.0, 4.0)
    print("length", p.length())
    print(describe(Circle(1.0)))


main()

异常处理

文件、网络等原语失败时会抛出异常。raise 抛出， try / except / finally 捕获，except 可以命名内置错误种类。

errors.cf
def read_or(path: str, fallback: str) -> str:
    try:
        return io.read(path)
    except IoError as e:
        print("could not read:", e)
        return fallback
    finally:
        print("read_or finished")


def must_be_positive(n: int) -> int:
    if n <= 0:
        raise ValueError("expected a positive number")
    return n


def main():
    print(read_or("missing.txt", "(default)"))
    try:
        must_be_positive(0)
    except ValueError as e:
        print("caught:", e)


main()

集合

列表与字典都有方法：列表有 append / pop / insert / remove / index / contains / sort / reverse / len，字典有 get / set / has / keys / values / items / remove / clear。 索引 xs[i] 与 d[k] 读写都可，读缺失键会抛出可捕获的错误。

collections.cf
def main():
    xs = [3, 1, 3, 2]
    xs.append(5)
    xs.sort()
    print("sorted", xs, "len", len(xs))

    tally = dict()
    for x in xs:
        if tally.has(str(x)):
            tally[str(x)] = tally[str(x)] + 1
        else:
            tally[str(x)] = 1
    print("tally", tally)

    # collections 模块提供常用高阶操作
    print(collections.unique(xs))
    print(collections.min_max(xs))
    print(collections.group_count(["a", "b", "a"]))
    print(sorted(map(def(n): return n * 2, xs)))


main()

模块与导入

一个 .cf 文件就是一个模块，用 module 名字 声明模块名、 用 import 名字 引入其它模块。标准库模块始终可用，写短前缀即可（math.sqrt）。

greet.cf
### 一个可被其它文件导入的小模块
module greet


def hello(who: str) -> str:
    return "Hello, " + who + "!"
app.cf
import greet


def main():
    print(greet.hello("Colorful"))


main()
终端
colorc app.cf -o build/app -I .
build/app

用 -I 目录 追加模块搜索路径（可重复），--stdlib 目录 指定标准库位置。工具会依次查找当前文件目录、-I 目录与标准库目录。

标准库

21 个模块，全部无需 import，用短前缀调用（strings.pad_left(...)）。 详细签名可用 colordoc 生成文档，或直接在编辑器里悬停查看。

GUI 编程

gui 是立即模式的绘制层（矩形、文本、图标、按钮、回调）， widgets 在上面提供声明式组件：把窗口描述成一棵树，返回给渲染器。 组件构造器返回的对象带有链式修饰方法（gap、pad_to、 sized_to、grown、expand_in、bg、 tint、font、on_tap、scrolls）。

counter.cf
import gui
import widgets


def on_tap(id: str) -> bool:
    gui.state_inc("count", 1)
    return True


def on_reset(id: str) -> bool:
    gui.state_set("count", 0)
    return True


### 每帧调用一次：返回组件树，渲染器负责布局与绘制
def build(n: int) -> widgets.Widget:
    page = widgets.scaffold(
        widgets.app_bar("Counter"),
        widgets.column([
            widgets.elevated_card(
                widgets.column([
                    widgets.title("Tapped " + str(gui.state_get("count")) + " times"),
                    widgets.label("Material 3, rendered natively").gap(4.0),
                ]).gap(8.0).pad_to(16.0),
            ),
            widgets.row([
                widgets.filled_button("tap", "Tap me", on_tap),
                widgets.tonal_button("reset", "Reset", on_reset),
            ]).gap(12.0),
        ]).gap(16.0).pad_to(24.0),
    )
    return widgets.with_fab(page, widgets.fab("add", "add", on_tap))


def main():
    widgets.light()
    widgets.show("Counter", 480, 640, build)


main()

应用状态放在 gui.state_*（模块本身没有全局变量），回调是普通函数、 只接收组件 id。窗口大小改变时布局会自动重算，因此不需要手写重排逻辑。

测试

以 test_ 开头的无参函数会被 colortest 自动发现并编译成一个驱动运行。

math_test.cf
def add(a: int, b: int) -> int:
    return a + b


def test_add_works():
    test.assert(add(2, 3) == 5, "integers add up")


def test_strings_helper():
    test.assert_equal_str(strings.pad_left("7", 3, "0"), "007", "padding pads")
终端
# 运行当前文件里的全部测试
colortest math_test.cf

# 运行整个目录，只跑名字里带 add 的用例
colortest -k add tests/

# 只列出会发现哪些用例（不编译）
colortest --list tests/

在 VSCode 里，Testing 侧边栏会自动列出工作区中所有 test_* 用例， 点击即可运行并看到逐条结果。

包管理

多文件项目用 colorful.toml 描述：包名、入口文件、构建参数与依赖。 colorpkg 提供脚手架与常用命令。

终端
colorpkg init myapp        # 生成 colorful.toml 与 src/main.cf
cd myapp
colorpkg build             # 构建
colorpkg run               # 构建并运行
colorpkg test              # 运行测试
colorpkg add mathx@1.0     # 记录依赖到 colorful.toml
colorpkg lock              # 写出 colorful.lock
colorpkg list              # 列出依赖
colorful.toml
[package]
name = "myapp"
version = "0.1.0"
entry = "src/main.cf"

[build]
opt = 2

依赖放在 vendor/<名字>/，构建时会自动加入模块搜索路径， 因此 import 名字.子模块 直接可用。

工具链参考

colorc — 编译器

参数 说明
-o, --output <path>输出文件（默认 a.exe）
--emit <kind>exe / object / llvm / c / wasm / tokens / ast / hir / mir
--backend <kind>auto / llvm / c
--opt <0-3>优化级别（默认 2）
--run构建成功后立即运行
-I, --search <dir>追加模块搜索路径（可重复）
--stdlib <dir>标准库目录
-L, --lib-dir <dir>runtime 库目录（libcolorful.cll 等）
--static-runtime / --shared-runtime静态或动态链接 runtime
--time / -v打印各阶段耗时 / 详细日志

colorlsp — 语言服务器

终端
colorlsp --stdio                    # 编辑器以 stdio 方式连接
colorlsp --stdio --stdlib D:\stdlib

支持 LSP 3.17：诊断、补全、悬停、定义、引用、重命名、文档符号、签名帮助与格式化。

colorfmt — 格式化

终端
colorfmt src\main.cf            # 就地格式化
colorfmt --check src            # 只检查，未格式化时退出码为 1
colorfmt - --stdout < main.cf   # 标准输入输出（编辑器用的就是这条）
colorfmt --indent 4 src

colortest — 测试

参数 说明
--list列出会发现的用例
--json输出机器可读结果
-k, --filter <N>只运行名字包含 N 的用例
--driver只打印生成的驱动，不运行
--keep保留生成的驱动与可执行文件
-I <dir> / --stdlib <dir>模块与标准库搜索路径

每个测试文件会单独生成一个驱动，所以不同文件里的同名类型互不干扰。

终端

常见问题

状态栏没有出现 Colorful

说明语言服务器没有启动。执行 Colorful: Show Output Channel 查看 Colorful Language Server 通道；把 colorful.logging.level 设为 debug 后，Colorful 通道会打印工具查找过的每个目录， 直接告诉你它去过哪里。最常见的原因是工具不在查找路径里，用 colorful.languageServer.path 指过去即可。

打字时没有出现新的诊断

诊断是随编辑实时推送的（通常几十毫秒）。如果完全没有任何诊断，先确认服务器已连上 （状态栏显示 Colorful）。若只想在保存时看到结果，可以先用 Colorful: Restart Language Server 重启一次。

找不到 colorc / colorfmt / colortest

插件内置版本会在「插件目录 → server → 平台」下被自动发现。如果你换用了自己构建的版本， 把 colorful.compiler.path 等设置指向它们；工作区里 build/ 下的产物也会被自动优先使用。

保存时没有自动格式化

扩展默认不改动你的编辑设置。在工作区设置里加上：

.vscode/settings.json
{
  "[colorful]": {
    "editor.formatOnSave": true
  }
}

整数除法结果不对

这是设计如此：/ 总是返回 float。 需要整数商请用 //。

构建时报错找不到标准库

显式传目录即可：colorc app.cf --stdlib <标准库目录>。 插件里的运行、构建、测试命令会自动带上内置标准库路径，无需手动指定。

还有问题？ 在 插件仓库 或 语言仓库 提 issue，附上 colorlsp --version 的输出与输出通道里相关的那几行。
