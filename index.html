写起来像脚本，跑起来是原生

Colorful 是一门静态类型的编译型语言。源码由 colorc 直接编译成机器码， 没有解释器、没有字节码；标准库自带 JSON、正则、HTTP、路径、编码、日志与环境变量， gui 与 widgets 模块用声明式写法渲染 Material 3 界面。 配套 colorlsp 语言服务器与 VSCode 扩展，安装后开箱即用。

### 一个 Material 3 窗口：声明式描述，原生渲染
import gui
import widgets


def on_tap(id: str) -> bool:
    gui.state_inc("count", 1)
    return True


def build(n: int) -> widgets.Widget:
    return widgets.scaffold(
        widgets.app_bar("Counter"),
        widgets.column([
            widgets.title("Tapped " + str(gui.state_get("count")) + " times"),
            widgets.filled_button("tap", "Tap me", on_tap),
        ]).gap(16.0).pad_to(24.0),
    )


def main():
    widgets.light()
    widgets.show("Counter", 480, 640, build)

为什么是 Colorful

它想同时满足四件在别处常常要分开取舍的事。

脚本的写法，原生的产物

缩进即块、类型推断、f-string，写起来接近脚本语言；colorc 把它编译成 单个可执行文件，交付时拷一个文件就走。

界面与语言一起设计

GUI 是语言自带模块：布局是纯函数，绘制与命中测试共用同一批原生原语， 点到的位置就是画出来的位置。

工程链一次配齐

编译器、语言服务器、格式化、测试、包管理、文档生成从第一版就在， 不用自己拼装工具。

标准库看得懂

标准库是明文 .cf，可以阅读、替换、扩展，而不是只能调用的黑盒。

完整简介：为什么创建、用什么实现、能做什么 →

语言本身

编译器把你写的每一行都检查一遍，再把检查过的程序编译成原生可执行文件。

静态类型，编译期报错

每个函数、每条分支都经过解析与完整类型检查，错误带上稳定的编号（形如 CF2046），可以直接搜索定位。

编译成原生，无需运行时

colorc 走 LLVM 或内置的 C 后端，产物是普通可执行文件：没有解释器、 没有虚拟机、没有启动开销。

结构化异常

raise / try / except / finally 是一等语法，底层文件与网络的原语失败会抛出可捕获的异常。

19 个标准库模块

JSON、正则、HTTP、文件与路径、文本与集合、命令行、日志、时间、随机、环境变量、 hex/base64/percent 编码、单元测试，全部开箱可用。

Material 3 原生 GUI

gui 直接调用 Direct2D 与 DirectWrite， widgets 提供 Flutter 风格的声明式组件与链式修饰方法。

工具链齐全

编译器、语言服务器、格式化、测试、包管理、runtime 打包各司其职， 并且都提供命令行与可编程接口。

快捷安装

三条路线，按你的目的挑一条：只想写代码、想在 Windows 上构建、或者想跨平台构建。

路线一 · 只要编辑器就能写（最快）

VSCode 扩展里已经打包了 colorlsp、colorc、 colorfmt、colortest、colorpkg 与完整 runtime、标准库，装完即可获得语法高亮、实时诊断、补全、跳转与格式化。

  1. 安装 Visual Studio Code
  2. 从 发布页 下载 colorful-lang-0.1.0.vsix
  3. 安装扩展，然后重新加载窗口
终端
code --install-extension colorful-lang-0.1.0.vsix --force
# 然后在 VSCode 里执行一次 Developer: Reload Window

打开任意 .cf 文件：状态栏出现 Colorful，打字时错误即时标红。

路线二 · Windows 上从源码构建

需要 MSVC 的 C++ 生成工具，构建脚本会一次性编译编译器、runtime 与全部工具。

  1. 安装 Visual Studio 生成工具（勾选「使用 C++ 的桌面开发」）
  2. 克隆仓库并运行构建脚本
命令提示符
git clone https://github.com/colorful-lang/colorful.git
cd colorful
scripts\build-windows.bat

# 产物在 build\ 下：colorc.exe、colorlsp.exe、colorfmt.exe ...

路线三 · CMake 构建（跨平台）

macOS 与 Linux 走这条路；Windows 同样适用。可选链接 LLVM 以获得进程内代码生成。

终端
cmake -S . -B build
cmake --build build --config Release

# 产物：build/bin/{colorc,colorlsp,colorfmt,colortest,colorpkg}

需要 CMake 3.20+ 与一个 C11/C++20 编译器。

校验安装

构建完成后，用仓库里的示例验证一遍流水线。

终端
build\colorc.exe examples\hello.cf -o build\hello.exe
build\hello.exe

build\colortest.exe --stdlib stdlib tests\e2e\test_core.cf

第一条命令编译并运行第一个程序，第二条运行端到端测试套件。

工具链

每个工具都能单独使用，也都能被编辑器与脚本调用。

工具 作用 常用命令
colorc 编译器：源码到原生可执行文件，可输出 C、LLVM IR 或直接运行 colorc app.cf -o build/app
colorlsp 语言服务器：诊断、补全、悬停、跳转、引用、重命名、符号、签名帮助、格式化 colorlsp --stdio
colorfmt 格式化：整文件或标准输入输出，可做检查模式 colorfmt -i src
colortest 测试：发现 test_* 函数、编译驱动并运行 colortest --json tests
colorpkg 包管理：脚手架、构建、运行、依赖与锁文件 colorpkg init
colorlib runtime 打包：静态库、动态库、头文件、字体与加密模块归档 colorlib build --out lib
